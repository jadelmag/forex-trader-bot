Resumen rápido

Sí hay causas claras que impiden abrir operaciones long y short.
Long (BUY) solo se intentan abrir en algunos casos; Short (SELL) prácticamente nunca se intentan abrir con el flujo actual.
Hay ambigüedad en cómo se interpreta la señal -1 de las estrategias de velas: a veces se usa como “cerrar largo”, otras debería ser “abrir corto”. El código actual no las distingue.
Hay validaciones que pueden bloquear operaciones aunque existan señales: capital mínimo, periodo de espera, límites por vela/estrategia y filtrado por escenario de mercado.
No veo que el dibujo de velas sea la causa; el streamer ya corrige el posicionamiento.
Hallazgos por fichero clave

app/gui_main.py (método GUIPrincipal._process_candle_async)
Forex:
Solo se procesa BUY: if Signal == 1 entonces se llama a _procesar_senal_compra_risk_manager_async. No existe rama para SELL (Signal == -1). Resultado: nunca se abre una operación corta con estrategias Forex.
Candle strategies:
Se usa CandleStrategies y se toma ExecSignal/Signal. Cuando current_signal == -1, se llama a risk_integration.procesar_senal(senal=-1, ...), lo cual el Integration interpreta como “cerrar operaciones de esa estrategia” y no como “abrir un corto”.
No se hace distinción entre “-1 de entrada” (abrir corto) y “-1 de salida” (cerrar largo). Pero el DataFrame devuelve también Position, que sí permite distinguir evento de entrada vs salida. Esto no se está usando.
Patrones (patterns):
Solo abre BUY cuando Signal == 1. No hay apertura SELL para patrones.
Esperas y límites:
wait_candles: mientras no llegue a 0, no se abre nada. Además, para estrategias de velas se exige len(df) >= wait_candles (se reutiliza como histórico mínimo).
Se limita a 1 forex por vela y 2 velas/patrones por vela. Correcto, pero limita aperturas simultáneas.
Escenario de mercado:
Se detecta y se loguea dos veces en el mismo método (duplicado de lógica). No afecta a la operativa pero genera ruido y consumo innecesario.
Capital:
El RiskManager se crea en init con capital 0. Si el usuario no pulsa “Añadir” dinero, el capital sigue en 0 y RiskManager rechaza aperturas por “Capital insuficiente” (mínimo 100 por defecto en config/app_config.json). Aunque más adelante hay un bloque para inicializarlo en simulación, normalmente ya existe la instancia y no se re-inicializa, así que se queda con 0 salvo que el usuario ponga dinero.
strategies/risk_manager_integration.py (RiskManagerIntegration._process_single_signal)
Con senal == -1 el comportamiento actual es “cerrar por estrategia”, no “abrir SELL”.
Esto hace que incluso si quisiéramos abrir cortos desde CandleStrategies, en la práctica se cierran largos en lugar de abrirse cortos.
strategies/risk_manager.py
Valida capital mínimo con _get_capital_limit() leyendo config/app_config.json (por defecto 100). Si capital < límite, se bloquea cualquier apertura (last_error = "Capital insuficiente...").
Gestión de SL/TP y cierres funciona. También hay límite de slots/operaciones activas.
strategies/strategies.py (ForexStrategies)
Muchas generan Signal = -1 para condiciones bajistas, pero el GUI no tiene rama para abrir SELL. Por eso “no se abren shorts” aunque haya señales.
strategies/candle_strategies.py
Devuelve Signal y ExecSignal y además Position, con una lógica de “entrada/salida” completa.
ExecSignal se usa para entradas y salidas. Sin embargo, el GUI trata cualquier -1 como “salida” y no como “entrada short”, causando la ambigüedad operativa.
strategies/market_strategy_mapper.py
Filtra por escenario: en UPTREND bloquea SELL y en DOWNTREND bloquea BUY para varias estrategias. Si ves muchos “🚫 ... bloqueada”, el escenario actual está bloqueando la señal. Esto es correcto por diseño, pero puede dar la sensación de “no funciona” si el escenario no permite el tipo de señal.
patterns/candlestickpatterns.py
Los patrones ahora están bien parametrizados y devuelven señales coherentes (correcciones previas aplicadas). No es la causa de que no se abran operaciones.
trading_view/candle_streamer.py
Ya se corrigió el posicionamiento (no centrado en el timestamp). No hay indicios de que el dibujado esté causando el problema de interpretación de patrones ahora.
Causas raíz

No hay ruta de apertura SELL en el GUI para Forex ni para Patrones. Para CandleStrategies, -1 se usa como “cerrar por estrategia”, no como “abrir corto”.
Ambigüedad de la señal -1 de CandleStrategies: el GUI no usa la columna Position para diferenciar si -1 es “salida de largo” o “entrada corta”.
Validaciones que bloquean aperturas:
Capital insuficiente (capital < capital_limit, por defecto 100).
Espera de velas (wait_candles) aún no cumplida.
Filtrado por escenario (MarketStrategyMapper) bloquea señales contrarias al escenario.
Lógica duplicada de detección de escenario (ruido, no bloqueo).
Código legacy conviviente (métodos antiguos de apertura/cierre sin RiskManager) que ya no se usan; no bloquea, pero añade complejidad.
¿Se están generando ambigüedades que bloquean aperturas/cierres idóneos?

Sí. Con CandleStrategies, ExecSignal = -1 puede significar “salir de largo” o “entrar en corto”. El GUI lo trata siempre como “cerrar” y nunca como “abrir corto”. Resultado: no se ejecutan cortos y, en algunos casos, se cierran largos de forma inmediata cuando quizás se pretendía rotar a corto.
¿Hay código duplicado?

Hay duplicidad de la detección de escenario dentro de _process_candle_async y conviven métodos antiguos como _procesar_senal_compra (sin RiskManager) junto a la versión con RiskManager. No rompen nada, pero conviene limpiar para menor confusión.
¿Se dibujan mal las velas?

No. El streamer ya posiciona las velas correctamente en el timestamp (corrección aplicada). No es la causa.

¿Por qué no se abren long y short?

Short: porque el GUI no implementa apertura SELL (Forex/Patrones) y para CandleStrategies el -1 se interpreta solo como “cerrar”, no como “abrir corto”.
¿Hay errores que bloqueen?
Capital insuficiente (< capital_limit).
No hay ruta de apertura SELL.
Ambigüedad de -1 sin usar Position para distinguir entrada/salida.
Bloqueos por escenario de mercado.

Sí generan señales. El problema es cómo se usan: falta de ruta SELL y ambigüedad en -1.
¿Ambigüedades que bloquean apertura/cierre idóneo?
Sí. -1 de CandleStrategies debe diferenciarse con Position entre “exit long” y “entry short”.

Sí, duplicada la detección de escenario al final de 
_process_candle_async
. También coexisten métodos legacy no usados.
¿Velas mal dibujadas?
No: el fix de posicionamiento está aplicado y no parece relacionado con la no apertura de operaciones.
